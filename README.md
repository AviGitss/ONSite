# Open Netrikkan website — GitHub + Vercel + Supabase

| Layer | Where | What |
|---|---|---|
| Source | GitHub | this repo |
| Frontend | Vercel | static `public/` built by `node build.js`; `vercel.json` proxies `/api/*`, `/stream/*`, `/download/whitepaper` to Supabase |
| Backend | Supabase project `jbisnfqijtmyhqgtogld` | table `website_leads` (RLS on), private buckets `site-videos` + `site-docs`, edge function `site-api` (**already deployed**) |

## Deploy steps
1. **GitHub** — `git init && git add . && git commit -m "Open Netrikkan site" && git branch -M main`, create an empty repo, then `git remote add origin <url> && git push -u origin main`. (`private/` media is git-ignored.)
2. **Media → Supabase Storage** (once): `SUPABASE_SERVICE_ROLE_KEY=<key> ./scripts/upload-media.sh` (key from Dashboard > Project Settings > API).
3. **Vercel** — Add New Project > import the repo. Settings come from `vercel.json` (build `node build.js`, output `public`). No env vars needed. Or CLI: `npx vercel --prod`.
4. Test: open the site, submit the whitepaper form with a company email, play a video, use the chatbot. Leads appear in Supabase > Table Editor > `website_leads`.

## Redeploying the edge function
Edit `supabase/functions/site-api/*`, then `supabase functions deploy site-api --no-verify-jwt --project-ref jbisnfqijtmyhqgtogld`. `content.mjs` is regenerated by `node build.js` from `data/content.js`.

## Local development
`npm start` → http://localhost:3000 (same API core, file store: `data/leads.jsonl`, media in `private/`).

## Notes
- Video protection is deterrence only (signed short-lived tokens, UA-bound, byte-range chunks, no-download UI, watermark). A viewer can always capture what they can watch.
- Leads are in `website_leads`; RLS has no policies so only the service role (edge function) can read/write.
- The token secret is derived from the service-role key; rotating that key invalidates outstanding tokens only.
- Edge function lives in the shared `opennetrikkan` Supabase project.
